# RoutePilot 桌面开发

桌面端采用 Tauri 2 和 Mihomo，包含 Windows、macOS 和 Linux 平台实现。首次启动保持系统代理关闭。桌面端从操作系统读取进程路径、PID、启动时间、本机 IP 与 DNS，从 Mihomo 读取节点、分组、规则、订阅、活动连接和流量统计。没有连接内核时显示空状态。独立 HTML 继续作为交互原型使用。

Mihomo 管理接口使用动态回环端口和随机认证令牌。桌面端支持规则、全局和直连模式，节点延迟、下载测速以及网站响应检测。下载测速经独立的本机代理入口下载 1 MB 样本，结果随线路和测速服务器变化。出口 IP 通过「网络详情」的检测按钮读取。

## 开发与验证

```powershell
npm install
npm run desktop -- dev
npm test
cargo test --manifest-path src-tauri/Cargo.toml
```

`npm run build` 会生成桌面前端资源。本地开发使用 `npm run desktop -- dev`。前端入口是 `index.html` 和 `src/main.ts`，浏览器预览使用演示数据。

## 桌面配置

- 在「订阅导入」粘贴 HTTPS 订阅或节点分享链接，也可以导入包含节点的 Clash YAML、逐行分享链接或 Base64 文件。添加后启动本机监听以加载节点，Windows 系统代理和 TUN 由首页的开关控制。
- 分流规则和分组支持在内核运行时编辑、启停及应用。程序规则使用 Windows 返回的完整路径，程序重启后仍可按路径匹配。移出分组会保留规则与原来的独立出口。替换整份 Mihomo JSON 时需要停止内核。监听端口支持运行时保存，通过 PATCH 热更新并同步当前由应用接管的系统代理；端口冲突或保存失败会尝试恢复原配置，切换可能影响现有连接。
- 策略组可手选、自动测速或故障切换，也可引用订阅来源。删除仍被规则或分组使用的订阅会先提示清理引用。连接记录从 Mihomo 日志流接收并保留本次会话最近 500 条路由事件。
- 主窗口以普通权限运行。开启全局 TUN 时，先显示应用确认弹窗，再由 Windows 授权 TUN 后台。关闭 TUN 会停止该后台，并恢复常规本地代理监听。严格的仅指定程序接管仍待实现。
- 「按软件」归并同一 Windows 安装包内的进程，以及可通过安装目录和文件名前缀确认的辅助程序。「按进程」逐项展示 PID 和线程数，软件行可以查看所属进程并选择要配置分流的可执行路径。

## 分流规则与实测

在「分流与程序 → 添加规则」可以组合程序路径、域名或 IP 网段，以及目标端口。每个已填写的条件都要匹配。粘贴网址时取主机名，端口在端口栏单独填写。选择「所有订阅」可复用个人规则，切换到缺少对应出口的订阅时会提示选择替代出口。

「规则生效顺序」列出实际生成的规则，包括局域网直连和末尾默认出口。使用托管配置时可以切换到手动顺序，例如将单个 IP 的代理例外移到局域网直连之前。完整配置按文件顺序生效。「连接记录 → 活动连接」显示内核报告的进程、命中条件与出口链，可用当前连接预填一条新规则。

在 macOS 上运行 `python3 scripts/smoke-routing.py <随包内核路径>`，可用 Python 和 curl 验证进程、目标、端口、IPv4 顺序和 IPv6 网段边界。测试通过回环监听观察内核实际选择的策略组。

### 在 Clash 中使用固定节点

在「代理组与节点 → 固定 SOCKS5 入口」添加节点和本机端口。内核停止时点「启动本地监听」。入口仅监听 `127.0.0.1`，支持 TCP 和 UDP，UDP 转发还取决于所选节点。订阅节点按订阅及节点名绑定；切换首页出口后仍用原节点，订阅移除该节点后入口会拒绝连接。

点「Clash 配置…」复制片段，将代理节点和 ChatGPT 进程规则分别并入 Clash 的现有配置。Clash 需要处于规则模式，能接管该应用并识别其联网进程。保留其他规则和默认出口；在此用法下，Xeylroute 只需本地监听。

在 GitHub Actions 手动运行 **Windows network acceptance**，可选择 Windows Server 2022 x64 或 Windows 11 ARM64。测试会在一次性虚拟机里操作桌面开关，向回环 HTTP 服务发送请求，并检查 WinINet、实际出口网卡和 Mihomo 命中日志。Windows 11 另用一台临时机运行 sing-box 对照实验。

## 内核打包与验证

桌面开发和打包会按目标架构获取官方 Mihomo v1.19.34，核对 SHA-256 后由 Tauri 随应用一起分发。支持 macOS、Windows、Linux 的 x64 和 arm64。首次安装后可直接进入「订阅管理」导入订阅或节点。本机验证也可以使用 [回环验证配置](./scripts/mihomo-loopback-example.json)。

运行 `npm run desktop -- build` 制作当前平台安装包。独立执行 Cargo 测试前先运行 `npm run core` 准备打包资源。内核版本与校验值在 `scripts/core-lock.json`，许可证随包附带。 [Mihomo 对应版本源码](https://github.com/MetaCubeX/mihomo/tree/v1.19.34)

工具栏「测延迟」和节点页「全部测延迟」通过 Mihomo 并发探测，最多同时测 8 个目标。网站连通性测试使用同一并发上限。节点页「测全部带宽」逐个下载 1 MB 样本，速度包含建连与首字节等待。全局 TUN 支持按程序规则选择出口。当前内核缺少桌面按进程路径限定 TUN 入站的能力，选择旧配置「仅指定分组和程序」时，应用会阻止启动全局 TUN。

可以通过 `python3 scripts/smoke-mihomo.py --binary <随包内核路径>` 验证本地转发、控制接口、订阅和测速。脚本只使用临时配置和回环端口。

启动后通过本应用查看监听状态，必要时在同一目录查看 `mihomo.log`。验证入口限制为本机 HTTP、SOCKS5 或混合监听。端口产生冲突时会提示。需要真实接管时，内核启动后点击「启用 Windows 代理」。状态会显示在网络详情。点击恢复、停止内核或正常退出应用时，系统代理会尝试恢复原值。内核异常退出由后台检查并恢复；应用异常退出后的恢复会在下次启动时执行。只有当前值仍与 RoutePilot 写入值一致时才恢复，以保留其他应用后续改动。

已使用官方 Mihomo v1.19.34 验证回环 HTTP 转发、认证管理接口、配置热重载、本地订阅刷新、分享链接与 Base64 解析，以及独立节点测速入口。复查可运行 `python scripts/smoke-mihomo.py <ZIP 路径>`。测试使用随机回环端口。前端验证构建复用了本机已有的 Vite 7.3.6。

Windows Server 2022 x64 已通过 47 项后端测试和单独执行的 WinINet 接管恢复测试。重复开启后仍可恢复原值；其他程序改写系统代理后，关闭接管会保留新值。桌面 TUN 后台也通过了单地址路由的安装、实际命中和退出清理测试。[Windows 验收日志](https://github.com/likehao19/Xeylroute/actions/runs/44757513856)

### Windows 11 ARM64 隔离验收

47 项后端测试与单独执行的 WinINet 接管恢复测试均通过。以下操作通过真实桌面控件、系统接口及网络请求验证。[Windows 11 验收日志](https://github.com/likehao19/Xeylroute/actions/runs/44766599122)

| 场景 | 实测结果 |
| --- | --- |
| 首页系统代理开关 | 开启后，采用 Windows 系统代理的客户端成功访问测试站点。关闭后恢复原代理设置。 |
| 全局 TUN | 在应用内取消授权提示，测试地址沿用原出口。确认后，测试连接进入 TUN 并命中配置的规则。正常关闭后恢复原出口。 |
| 接口切换 | TUN 运行期间，为单个测试地址临时添加宿主网卡路由，Windows 选用了该网卡。移除路由后，同一目标重新经过 TUN。 |
| 异常退出 | 系统代理与 TUN 同时开启时强制结束桌面进程，Windows 释放了 TUN 路由。重启应用后，WinINet 设置恢复原值。 |
| 按软件和实例分流 | Mihomo 能按程序选择出口。同一路径的两个并行实例及重启后的新实例都会继承路径规则。选中的 curl 和未选中的 Python 都进入了 TUN。 |

备选内核 sing-box 1.14.4 的实验在 TUN 上设置了 `include_package`。curl 与两个 Python 实例的连接都到达了受控出口，按端口分流的阳性对照也命中了指定出口。程序名对照未命中，因此这次实验无法确认按 PID 区分实例的能力。[对照实验日志](https://github.com/likehao19/Xeylroute/actions/runs/44766599122/job/136392754984)

严格按软件限定 TUN 入站、只对某个 PID 实例生效的临时规则仍待实现。Windows 系统 UAC 的授权与取消、托盘菜单正常退出、Wi-Fi 与以太网实机切换，以及外部订阅线路测速仍待交互式验收。托管测试机没有暴露可操作的托盘图标时，工作流会在摘要中标注托盘验收未完成。
